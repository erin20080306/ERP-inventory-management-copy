# 多語言（繁體中文／English）實作說明

更新日期：2026-09-11

本系統採 **next-intl「無語言路由」模式**：後台網址完全不變，語言由使用者設定決定；
只有對外官網與商城會在網址帶語言前綴，讓搜尋引擎能分語言收錄。

---

## 一、語言怎麼決定

優先序由高到低（`src/i18n/locale.ts`）：

1. **對外網址前綴** — `/en/store/acme` 一定是英文，分享連結不會因人而異。
2. **NEXT_LOCALE Cookie** — 登入後由中介層依使用者資料庫設定同步。
3. **瀏覽器 Accept-Language** — 只在使用者從未選過語言時作為後備。
4. **系統預設** — `zh-TW`。

### 為什麼不是每次請求都查資料庫

`User.locale` 是**真正的來源**，但每個 Server Component 都查一次 User 會拖慢全站。
因此在 `middleware.ts` 由 NextAuth JWT 取出 `token.locale`，寫進 Cookie；
`getRequestConfig` 只讀 Cookie。管理員替員工改語言後，最多一分鐘內（JWT 重新驗證週期）生效。

## 二、網址規則

| 類型 | 範例 | 是否帶語言前綴 |
| --- | --- | --- |
| 後台 ERP／POS | `/pos`、`/sales`、`/dashboard`、`/medical` | **否**，維持原網址 |
| 對外官網／商城 | `/store/acme`、`/site/acme`、`/plans`、`/solutions` | 是，英文為 `/en/...` |

後台刻意不帶前綴，避免破壞既有書籤、iOS App 與 Electron 桌面版的硬編碼網址。
公開頁面會輸出 `hreflang` 與 `x-default`（`src/i18n/metadata.ts`）。

## 三、哪些字要翻譯、哪些不能翻

| 類別 | 作法 | 原因 |
| --- | --- | --- |
| 介面文字（按鈕、標題、提示） | `messages/*.json` | 純顯示 |
| 權限模組與動作名稱 | `permissions.*` 命名空間 | 純顯示 |
| **預設角色名稱** | 以角色代碼反查（`src/i18n/labels.ts`） | 名稱存在資料庫，屬主檔；自訂角色原樣顯示 |
| **標準會計科目名稱** | 以**科目代碼**對照（`src/lib/account-names-en.ts`） | 代碼是語言中立主鍵；自訂科目不翻譯 |
| **商品分類、商品名稱、客戶名稱** | **不翻譯** | 是資料，不是介面；翻了會讓篩選與比對失效 |
| **CSV 匯入／匯出欄位名** | **不翻譯** | 是檔案格式契約，翻了會讓既有範本失效 |
| 幣別代碼 | 取自租戶 `CompanySetting.currency` | 幣別是帳務事實，不隨介面語言改變 |

> 這條界線和 SAP Business One／NetSuite 一致：換語言只換「怎麼顯示」，
> 絕不會把 TWD 帳變成 USD 帳，也不會改寫任何主檔。

## 四、金額與日期

`src/i18n/format.ts` 提供語言感知的格式化：

```ts
// Server Component
const f = createFormatters(await getLocale(), companySettings.currency);
f.money(1234);          // 幣別來自租戶，格式跟著語言
f.dateTime(row.updatedAt);

// Client Component
const { money, dateTime } = useFormatters();
```

- TWD／JPY 等無輔幣的幣別一律進位到元，維持既有帳務規則。
- 時區固定為 `NEXT_PUBLIC_APP_TIME_ZONE`（預設 `Asia/Taipei`），
  **不跟著介面語言換**，避免跨時區把日結報表切錯天。

## 五、新增一個字串

1. 在 `messages/zh-TW.json` 與 `messages/en.json` **同時**加入相同的鍵。
2. 元件內取用：

```tsx
// Client
const t = useTranslations("pos");
<button>{t("checkout")}</button>

// Server
const t = await getTranslations("dashboard");
```

3. 執行驗證：

```bash
npm run test:i18n
```

`scripts/verify-i18n.ts` 會檢查：鍵是否對齊、英文是否還是中文、ICU 參數是否一致、
程式用到的鍵是否都存在、網址前綴規則、金額格式，以及標準科目英文對照是否完整。
CI 在型別檢查之後就會跑這一支。

## 六、新增一種語言

1. `src/i18n/config.ts` 的 `LOCALES`、`LOCALE_LABELS`、`LOCALE_BCP47`、
   `LOCALE_DEFAULT_CURRENCY` 各加一筆。
2. 複製 `messages/en.json` 成新檔並翻譯。
3. 跑 `npm run test:i18n`；缺鍵會直接失敗。
